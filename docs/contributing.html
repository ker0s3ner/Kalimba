Contribution flow

  1. Open an issue describing the player-facing problem.
  2. Keep a pull request focused on one coherent change.
  3. Run the relevant build or check before opening the PR.
  4. Include screenshots or a short clip for UI changes.

Standards

New Kotlin code follows the repository’s existing style and licensing headers. Keep module names descriptive, settings discoverable, and behavior server-aware. The project is GPL-3.0; see LICENSE for details.
